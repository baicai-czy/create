# Feature Specification: 联系问题处理

**Feature Branch**: `001-contact-issue-handling`

**Created**: 2026-08-04

**Status**: Draft

**Input**: User description: "联系问题处理"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 访客在线咨询提交 (Priority: P1)

网站访客在"联系我们"页面填写咨询表单（姓名、公司、电话、邮箱、感兴趣的服务、咨询内容），提交后系统自动保存并显示提交成功提示。

**Why this priority**: 这是联系功能的核心入口，没有提交通道就无法产生任何咨询记录。

**Independent Test**: 访问 /contact 页面填写并提交表单，验证成功提示出现且数据被保存。

**Acceptance Scenarios**:

1. **Given** 访客在联系我们页面，**When** 填写所有必填字段并点击提交，**Then** 显示"提交成功"提示，表单数据被保存
2. **Given** 访客未填写必填字段（姓名/公司/电话），**When** 点击提交，**Then** 显示对应的字段校验错误提示，表单不被提交
3. **Given** 访客填写了无效的手机号格式，**When** 点击提交，**Then** 显示"请输入正确的手机号"错误提示

---

### User Story 2 - 管理员查看和处理咨询 (Priority: P1)

管理员登录后台后，在"咨询管理"页面查看所有提交的咨询记录，可以按照类型（咨询/合作）和状态（待处理/处理中/已解决）进行筛选，点击某条记录查看详情。

**Why this priority**: 没有管理端处理能力，咨询表单就只是单向收集，无法形成闭环。

**Independent Test**: 登录 /admin → 咨询管理，验证列表显示所有咨询记录，可筛选和查看。

**Acceptance Scenarios**:

1. **Given** 管理员登录后台，**When** 进入咨询管理页面，**Then** 看到按提交时间倒序排列的咨询列表
2. **Given** 咨询列表中有不同类型的记录，**When** 管理员选择"仅看合作申请"，**Then** 列表只显示类型为"合作"的记录
3. **Given** 有新的咨询提交且查阅状态为"未阅"，**When** 管理员打开该咨询详情，**Then** 查阅状态自动变为"已阅"并在列表中醒目标识
4. **Given** 某条咨询处理状态为"待处理"，**When** 管理员将其标记为"已解决"，**Then** 处理状态更新且记录操作日志

---

### User Story 3 - 访客合作申请提交 (Priority: P2)

合作伙伴意向企业通过合作申请表单提交企业信息和合作需求，系统区分"咨询"和"合作"两种提交类型，合作申请额外包含行业和需求详情字段。

**Why this priority**: 合作申请是商务转化的重要渠道，比普通咨询有更高的商业价值。

**Independent Test**: 在 /contact 页切换到合作申请标签，填写并提交，验证数据保存类型为"cooperation"。

**Acceptance Scenarios**:

1. **Given** 潜在合作伙伴，**When** 在联系我们页选择"合作申请"并填写完整资料提交，**Then** 系统保存类型为"合作"且包含行业/需求字段
2. **Given** 管理员查看合作申请，**When** 点击某条合作记录，**Then** 看到完整的企业信息、行业和需求描述

---

### User Story 4 - 咨询状态通知 (Priority: P3)

当管理员更新咨询状态为"已解决"时，系统自动向提交者的邮箱发送处理结果通知，告知其问题已被处理。

**Why this priority**: 提升用户体验的闭环反馈，但不影响核心流程。

**Independent Test**: 管理员将某条咨询标记为"已解决"，验证系统触发邮件发送。

**Acceptance Scenarios**:

1. **Given** 某条咨询状态被更新为"已解决"，**When** 提交者提供了有效邮箱，**Then** 系统发送通知邮件到该邮箱

---

### Edge Cases

- 表单提交时网络中断：前端显示错误提示"服务器连接失败，请稍后重试"
- 同一用户短时间内重复提交：不做限制，每条提交独立保存
- 咨询内容包含特殊字符（emoji、SQL 注入代码）：系统正确存储和转义，防止安全问题
- 管理后台无咨询记录时：显示空状态提示"暂无咨询记录"
- 手机号格式异常（国际号码、短号）：前端做基本格式校验，后端不做严格限制

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供在线咨询表单，包含字段：姓名（必填）、公司（必填）、电话（必填）、邮箱（选填）、感兴趣的服务（下拉选择）、咨询内容（选填）
- **FR-002**: 系统 MUST 提供合作申请表单，包含字段：姓名、公司、电话、邮箱、行业、需求描述
- **FR-003**: 系统 MUST 对所有提交数据进行前端格式校验 + 后端二次校验
- **FR-004**: 系统 MUST 将提交数据持久化存储，包含提交类型（咨询/合作）、查阅状态（未阅/已阅）、处理状态（待处理/处理中/已解决）、提交时间
- **FR-005**: 管理后台 MUST 展示所有咨询记录列表，支持按类型、查阅状态和处理状态筛选
- **FR-006**: 管理员 MUST 能够更新咨询的处理状态（待处理→处理中→已解决）
- **FR-010**: 新咨询提交时查阅状态默认为"未阅"。管理员打开某条咨询详情后，系统 MUST 自动将其标记为"已阅"
- **FR-011**: 管理后台列表 MUST 对未阅条目显示：红色圆点标识 + 标题加粗字体 + 侧边栏"咨询管理"菜单显示未阅数量角标
- **FR-007**: 每次咨询状态变更 MUST 记录操作日志
- **FR-008**: 当咨询状态变更为"已解决"且提交者提供了邮箱时，系统 SHOULD 发送通知邮件
- **FR-009**: 全站任意页面 MUST 可通过"智能客服"按钮打开在线聊天窗口

### Key Entities

- **咨询记录 (Contact)**: 类型（咨询/合作）、姓名、公司、电话、邮箱、服务意向、咨询内容、查阅状态（未阅/已阅）、处理状态（待处理/处理中/已解决）、提交时间
- **操作日志 (Log)**: 关联管理员、操作类型、操作详情、操作时间

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 访客可在 2 分钟内完成咨询表单填写和提交
- **SC-002**: 表单提交成功率 ≥ 99%（非网络故障情况下）
- **SC-003**: 管理员可在 30 秒内定位并查看某条特定咨询的详情
- **SC-004**: 所有咨询状态变更在操作后 1 秒内反映在界面上
- **SC-005**: 90% 以上的表单提交包含有效的联系电话或邮箱

## Clarifications

### Session 2026-08-04

- Q: 咨询记录是否需要"未阅/已阅"的查阅状态，而不仅仅是处理状态（待处理/处理中/已解决）？ → A: 咨询状态在查阅并确定后可以从未阅变成已阅。新增"查阅状态"维度：未阅 / 已阅。管理员打开并查看某条咨询后，自动或手动标记为已阅。同时保留"处理状态"维度：待处理 / 处理中 / 已解决。
- Q: 管理后台列表中"未阅"状态的咨询应该如何视觉区分？ → A: 红色圆点 + 标题加粗 + 未阅数量角标（Option C 组合方案）

## Assumptions

- 访客使用现代浏览器（Chrome/Edge/Firefox/Safari 近 2 个主版本）
- 邮件发送功能由后端 SMTP 服务提供（当前为可选功能，暂不实现自动化）
- 智能客服聊天功能已通过 ServiceChat 组件实现
- 管理后台已有 RBAC 权限体系，客服人员角色可访问咨询管理
- 当前阶段不接入第三方在线客服系统（如美洽、智齿等）
